# Assumptions and Terms

## Use When

- A term has two possible meanings.
- A claim has no proof.
- The doc states a fact that the user did not say.

## Technique

Write each silent assumption as a statement.
Ask the user to confirm or to correct the statement.
Build a glossary during the interview. One term MUST have one meaning.
Ask for a definition when a term is vague.

Name the ambiguity class:

- Unclarity: the reader cannot parse the sentence.
- Multiple understanding: the words allow two readings.
- Incorrect disambiguation: the agent picks the wrong reading.

Check:

- Each assumption has a confirmed or open mark.
- Each repeated term has one glossary entry.

## Failure Mode

The design carries a hidden assumption. The team finds the assumption at build time.

Sources:

- Clark and Brennan, "Grounding in Communication", 1991 (common ground).
- Ferrari et al., "Ambiguity and Tacit Knowledge in Requirements Elicitation Interviews", 2016.
